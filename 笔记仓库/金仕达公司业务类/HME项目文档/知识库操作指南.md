# HME 知识库操作指南

## 一、架构速览

```
HME项目文档/
├── wiki/              ← 导航层：_MAP.md + 6个领域概览
├── 代码文档/           ← 详细层：按业务模块组织
├── 需求文档/           ← 详细层：按功能特性组织
├── 通用文档/           ← 详细层：跨模块共享知识
├── 错误分析-问题排查记录/ ← 详细层：Bug与排障
├── shturl.md          ← 变更日志（只追加，最新在前）
├── schema.md          ← 操作规则手册（唯一权威）
├── AGENTS.md          ← Agent启动协议（在Getting Started/下）
└── .claude/           ← Claude Code 集成配置
    ├── skills/        ← 自动触发技能（ingest / query）
    └── commands/      ← 斜杠命令（/ingest / /wiki-query）
```

**三层设计**：导航层（wiki）→ 详细层（文档目录）→ 追踪层（shturl + schema）

---

## 二、日常使用

### 摄入新文档

在 Claude Code 中进入 `HME项目文档` 目录，执行：

```
/ingest <文档路径或内容描述>
```

或自然语言触发（技能自动识别）：
> "帮我把这份XXX文档整理进知识库"

**摄入流程**（自动执行）：
1. 读取 → 分类（代码文档/需求/Bug/通用）
2. 按 schema.md 模板生成文档 + frontmatter
3. 建立关联（related字段、反向链接、正文wikilink）
4. 更新 wiki 导航层（领域页 + _MAP.md）
5. 追加 shturl.md 变更记录

### 查询知识库

```
/wiki-query <问题>
```

或自然语言触发：
> "点价单的业务流程是什么？"

**查询路径**：MAP → shturl → 领域wiki → 详细文档 → 带来源引用的回答

### 日常维护

| 操作 | 频率 | 做法 |
|------|------|------|
| 检查知识缺口 | 每周 | 查看 `wiki/_MAP.md` 底部"知识缺口" |
| 健康检查 | 每月 | 让 Agent 执行 schema.md 第9节 Lint 流程 |
| 清理过期文档 | 按需 | 检查 frontmatter `version` 和 `date` |
| 补充关联 | 每次摄入 | 确保新文档有 `related` 和反向链接 |

## 三、换工具初始化指南

当从 Claude Code 切换到其他大模型工具时，按以下步骤操作：

### 步骤 1：准备入口文件

新工具只需要读 3 个文件即可理解整个知识库：

| 文件 | 作用 | 读取顺序 |
|------|------|----------|
| `AGENTS.md`（Getting Started/） | 启动协议 + 文件位置表 | 1 |
| `schema.md` | 完整操作规则 | 2 |
| `wiki/_MAP.md` | 全局知识地图 | 3 |

### 步骤 2：适配新工具的指令系统

**如果新工具支持自定义系统提示词（System Prompt）**：

将 `AGENTS.md` 的内容作为系统提示词，核心是启动序列：
```
每次对话开始时，依次读取：
1. wiki/_MAP.md — 建立全局认知
2. shturl.md 前30行 — 判断时效性
3. schema.md — 理解操作规则
4. 相关 wiki/<领域>.md — 进入具体领域
5. 详细文档 — 深入回答
```

**如果新工具支持 MCP / 文件系统访问**：

确保它能访问 `HME项目文档/` 目录，并设置工作目录为该路径。

**如果新工具支持自定义命令/技能**：

参照 `.claude/skills/` 和 `.claude/commands/` 中的定义，在新工具中重建：
- **摄入命令**：对应 `schema.md` 第4节流程
- **查询命令**：对应 `schema.md` 第5节流程

### 步骤 3：验证初始化

向新工具提问以下问题，确认它能正确导航：
1. "这个知识库有哪些业务领域？"（应能回答6个领域）
2. "最近有什么变更？"（应能读 shturl.md）
3. "点价流程是怎样的？"（应能导航到作价与定价领域）

### 步骤 4：迁移检查清单

- [ ] 新工具能读取 `wiki/`、`代码文档/`、`需求文档/` 等目录
- [ ] 新工具理解 `[[wikilink]]` 语法并跟随链接
- [ ] 新工具摄入文档时遵循 `schema.md` 的 frontmatter 规范
- [ ] 新工具摄入后会更新 wiki 导航层和 shturl.md
- [ ] Obsidian 中的文档格式不受影响

## 四、关键约定速查

| 约定 | 说明 |
|------|------|
| `[[wikilink]]` | Obsidian 内部链接语法，跨文档引用 |
| `_` 前缀 frontmatter | 只读字段，Agent 不应修改 |
| `version` 字段 | 文档版本号，用于缓存新鲜度判断 |
| shturl 只追加 | 永远不修改历史条目，新条目加在最前面 |
| wiki 层只放摘要 | 详细逻辑放在详细层文档中 |
| 术语权威来源 | `通用文档/CTRM业务术语表/CTRM业务术语表.md` |
