## 一、报表概述

> [!abstract] 报表说明
> 这是一个**库存价值报表**（Detailed Entries Value），属于大宗商品贸易/仓储管理系统中的**月末（EOM）库存估值报表**。
> 
> **与评估表的核心区别**：本报表的数据**来自执行月结后写入的快照表**（`eom_storage_detail` + `eom_storage_added_value`），而非从源数据实时计算。

### 与库存价值评估表的对比

| 维度 | 库存价值报表 (本报表) | 库存价值评估表 |
|------|---------------------|-------------|
| **数据来源** | `eom_storage_detail` + `eom_storage_added_value`（月结快照表） | `document_items` 等源表（实时查询） |
| **是否依赖执行月结** | ✅ 必须有月结数据才有结果 | ❌ 不依赖月结，实时计算 |
| **时间维度** | 按**会计月** | 按**会计日** |
| **计算复杂度** | 中等（SQL聚合 + Java层补充计算） | 极高（fillEvaluationInfo ~1000行） |
| **缓存** | Redis 缓存 120 秒 | 无缓存 |
| **核心输出** | 记账金额、附加价、金属价、发票金额 | 记账金额、附加价、金属价、CD金额、关联/未关联拆分 |

### 核心计算内容

每条记录最终计算并展示：

- **数量类**：入库数量、冲销数量、已开票数量、待开票数量
- **金额类**：记账金额（accountingTotalValue）、附加价（addedValue）、金属价（metalValue）、发票金额（taxIncInvoiceAmount）
- **本位币折算**：上述金额均同时展示本位币版本

核心恒等式：

```
accountingTotalValue = metalValue + addedValue
```

## 二、`listDetailedEntriesValue` 方法分析

### 方法整体职责

该方法是报表的**入口方法**，负责四件事：
1. 从月结快照表查出骨架数据（CTE + UNION ALL）
2. 批量加载发票和冲销信息
3. 逐条补充计算 metalValue、开票状态覆盖等
4. 处理冲销单据取反

### 完整处理流程

```
═══════════════════════════════════════════════════════════════
  Step 1：参数预处理 + Redis 缓存检查
═══════════════════════════════════════════════════════════════

  lastDate = 2026-06-30（月末日期）

  缓存 key = "DetailedEntriesValue:" + query.hashCode()
  如果缓存命中（仅全量查询 size=-1 时）→ 直接返回

  Redis 控制参数：
    key = "EomControl:DetailedEntriesValue_offsetFlag"
    如果存在 → 强制设置 offsetFlag（控制是否显示冲销行）


═══════════════════════════════════════════════════════════════
  Step 2：SQL 查询骨架数据（CTE 四段式）
═══════════════════════════════════════════════════════════════

  result = baseMapper.listDetailedEntriesValue(query)

  SQL 结构（详见下方第三节）：

═══════════════════════════════════════════════════════════════
  Step 5：逐条补充计算（核心 Java 层逻辑）

  │                                                         │
  │ 5g. 收集零金额冲销行                                     │
```

## 三、SQL 详解（CTE 四段式）

### 3.1 CTE `latest` — 查找每个 documentItemId 的最新会计月

```sql
-- 第一部分：从 eom_storage_detail 查
SELECT 'esd' type, document_item_id, MAX(accounting_month_value) AS accounting_month_value
FROM eom_storage_detail esd
INNER JOIN eom_storage es ON es.id = esd.eom_storage_id
    AND es.inactive_flag = 0
    AND es.status != 10              -- 排除已冲销的月结单据
WHERE esd.inactive_flag = 0
    AND esd.status != 10             -- 排除已冲销的明细
    AND esd.latest = 1               -- 只取最新版本
    AND esd.accounting_month_value <= #{accountingMonthValue}  -- 不超过查询月
GROUP BY esd.document_item_id

UNION ALL

-- 第二部分：从 eom_storage_added_value 查（结构完全相同）
SELECT 'esav' type, document_item_id, MAX(accounting_month_value)
FROM eom_storage_added_value ...
```

**核心逻辑**：
- 同一个 `document_item_id` 可能在不同月份被执行过月结（latest=true 只保留最新一次）
- `MAX(accounting_month_value)` 取该明细在查询月份范围内的**最新会计月**
- 用 `type` 字段区分来源（`esd` = detail, `esav` = added_value）
- 排除 `status=10`（已冲销）的记录

### 3.2 CTE `new_accounting` — 从 detail 表取记账金额

```sql
SELECT
    main.physical_deal_id, main.document_item_id, main.action_id,
    main.legal_entity_id, main.storage_id, main.counterparty_id,
    main.business_department_id, main.business_segment_id,
    main.quantity_unit_id, main.product_id, main.currency_id,
    main.offset_flag, main.factory_code,
    es.accounting_month,                    -- 从月结主表取会计月
    main.title_transfer_date, main.document_number, main.posting_date,
    main.document_line_number, main.contract_line_number,
    main.delivery_in_quantity, main.delivery_in_quantity_unit_id,
    main.sap_batch_number, main.sap_contract_code,
    main.sap_contract_line_code, main.sap_document_code,
    main.sap_document_account_year, main.sap_document_item_code,
    main.base_currency_id,
    main.quantity,
    (main.offset_quantity * -1) offset_quantity,  -- 冲销数量取反显示

    main.accounting_total_value,                 -- ★ 记账金额（来自月结执行）
    main.base_cur_accounting_total_value          -- ★ 本位币记账金额
FROM eom_storage_detail main
INNER JOIN eom_storage es ON es.id = main.eom_storage_id
    AND es.inactive_flag = 0 AND es.status != 10
INNER JOIN latest ON latest.document_item_id = main.document_item_id
    AND latest.accounting_month_value = main.accounting_month_value
    AND latest.type = 'esd'                      -- 精确匹配 detail 类型
WHERE main.inactive_flag = 0 AND main.status != 10
```

### 3.3 CTE `new_added` — 从 added_value 表取附加价

```sql
SELECT
    -- 维度字段同上...

    main.invoiced_quantity,              -- 已开票数量
    main.uninvoiced_quantity,            -- 未开票数量
    main.added_value,                    -- ★ 附加价（来自月结执行）
    main.base_cur_added_value            -- ★ 本位币附加价
FROM eom_storage_added_value main
INNER JOIN eom_storage es ON ...
INNER JOIN latest ON ... AND latest.type = 'esav'  -- 精确匹配 added_value 类型
```

### 3.4 CTE `main` — LEFT JOIN 合并 + UNION ALL 补全

```sql
-- 第一部分：以 accounting 为主，LEFT JOIN added
SELECT
    main.*,                              -- accounting 的全部字段
    others.invoiced_quantity,            -- added 的开票数量
    others.uninvoiced_quantity,          -- added 的未开票数量
    others.added_value,                  -- added 的附加价
    others.base_cur_added_value          -- added 的本位币附加价
FROM new_accounting main
LEFT JOIN new_added others ON main.document_item_id = others.document_item_id

UNION ALL

-- 第二部分：以 added 为主，LEFT JOIN accounting（补全只有 added 没有 accounting 的记录）
SELECT
    main.*,
    others.accounting_total_value,       -- accounting 的记账金额
    others.base_cur_accounting_total_value
FROM new_added main
LEFT JOIN new_accounting others ON main.document_item_id = others.document_item_id
WHERE others.document_item_id IS NULL    -- 只取 accounting 中不存在的
```

**为什么需要 UNION ALL 双向补全？**
- 某些入库记录可能只执行了 Accounting Value 月结但没有 Added Value（如 Z001 原材料）
- 某些记录可能只有 Added Value 但没有 Accounting Value（罕见但可能存在）
- 双向 LEFT JOIN + UNION ALL 确保不遗漏任何记录

### 3.5 最终 SELECT — 关联 15+ 张维度表

```sql
SELECT
    main.*,
    di.source_document_item_id,              -- 上游单据ID（冲销用）
    di.quantity warehouseQuantity,            -- 仓库原始数量
    CONCAT(e.action_name, IF(offset_flag=1, ' reverse', '')) actionName,
    g.name counterpartyName,                 -- 交易对手
    f.name storageName,                      -- 仓库

    h.DEPT_NAME businessDepartmentName,      -- 业务组合

    b.contract_number,                       -- 合同号

    j2.name quantityUnitName,                -- 数量单位
    CONCAT(k.code, '-', k.name) productName, -- 商品
    CONCAT_WS('-', k2.code, k2.name) parentProductName,  -- 母合金
    l.name currencyName,                     -- 结算币种

    acd.code_name factoryName                -- 工厂
FROM main
    LEFT JOIN physical_deals b ON ...        -- 合同
    LEFT JOIN document_items di ON ...       -- 入库明细
    LEFT JOIN sys_company d ON ...           -- 机构
```

## 四、Java 层计算详解

### 4.1 MetalValue（金属价）计算

这是本报表最核心的 Java 层计算，SQL 只提供了 `accountingTotalValue` 和 `addedValue`，`metalValue` 在 Java 中推导：

```
  ┌─────────────────────────────────────────────────────────────┐
  │ metalValue 计算公式                                         │
  │                                                             │
  │  Part1 = accountingTotalValue × (未匹配量 / 仓库量)         │
  │          ↑ 按未开票比例拆出部分记账金额                       │
  │                                                             │
  │  Part2 = 发票金额 - addedValue                              │
  │          ↑ 已开票部分中属于金属价的部分                       │
  │          (冲销行: 发票金额 × -1)                             │
  │                                                             │
  │  metalValue = Part1 + Part2                                 │
  └─────────────────────────────────────────────────────────────┘
```

**公式解读**：

| 部分 | 含义 |
|------|------|
| `accountingTotalValue × (unmatchQty / warehouseQty)` | 记账金额中"未开票部分"的金属价占比 |
| `invoiceAmount - addedValue` | 已开票金额中扣除附加价后的金属价部分 |
| 两者相加 | 得到完整的金属价 = 未开票金属价 + 已开票金属价 |

**本位币版本同理**：
```
baseCurMetalValue = baseCurAccountingTotalValue × (unmatchQty / warehouseQty)
                  + (baseCurInvoiceAmount - baseCurAddedValue)
```

### 4.2 开票状态覆盖记账金额

```
              ┌─────────────────────────────────┐
              │ 开票状态判断：                     │
              │ invoiceStage = "Final"           │
              │ 或 unmatchQuantity ≤ 0           │
              └──────────┬──────────────────────┘
                         │
            ┌────────────┴────────────┐
            │ 完全开票                 │ 部分开票 / 未开票
            ▼                         ▼
  accountingTotalValue = 发票金额     accountingTotalValue = SQL值不变
  (覆盖SQL中月结执行的值)              (保持月结执行的计算值)

  baseCurAccountingTotalValue         baseCurAccountingTotalValue
  = 发票本位币金额                     = SQL值不变
```

**为什么完全开票时要覆盖？**
- 月结执行时的记账金额是按公式计算的估算值
- 完全开票后，发票金额才是最终准确值
- 报表展示时应以发票金额为准

### 4.3 CD Note 调整（附加价类型的发票）

```
              ┌─────────────────────────────────┐
              │ 是否存在 CdValuationType         │
              │ = ADDED_VALUE 的 CD Note 发票？  │
              └──────────┬──────────────────────┘
                         │
                ┌────────┴────────┐
                │ 有               │ 无
                ▼                 ▼
  ┌──────────────────────────┐   (不调整)
  │cdAddedValue =            │
  │ CD Note发票不含税金额     │
  │                          │
  │addedValue += cdAddedValue│  ← 附加价吸收CD金额
  │metalValue -= cdAddedValue│  ← 金属价扣减CD金额
  │                          │
  │本位币按比例调整：          │
  │baseCurAddedValue *=      │
  │  (addedValue+cdAddedValue)│
  │  / addedValue             │
  │                          │
  │baseCurMetalValue *=      │
  │  (metalValue-cdAddedValue)│
  │  / metalValue             │
  │                          │
  │(记账总额不变，内部再分配)   │
  └──────────────────────────┘
```

### 4.4 零金额冲销行的处理（Step 6）

这是一个特殊场景：某些冲销行在 SQL 中查出的 `accountingTotalValue = 0`，需要从原始单据复制金额并取反。

```
  ┌─────────────────────────────────────────────────────────┐
  │ 触发条件：                                               │
  │   offsetFlag = true                                      │
  │   且 accountingTotalValue ≈ 0（精度5位内）                │
  │                                                          │
  │ 处理流程：                                                │
  │                                                          │
  │ 1. 收集这些冲销行的 sourceDocumentItemId                  │
  │    → offsetSourceDocumentItemIdList                      │
  │                                                          │
  │ 2. 找出不在当前 resultMap 中的原始单据ID                   │
  │    → waitingExecIds                                      │
  │                                                          │
  │ 3. 递归调用 listDetailedEntriesValue 查询这些原始单据      │
  │    → execItems（递归但限制了 documentItemIdList，          │
  │      不会无限递归）                                       │
  │                                                          │
  │ 4. 合并到 resultMap                                      │
  │                                                          │
  │ 5. 遍历零金额冲销行：                                     │
  │    sourceItem = resultMap.get(sourceDocumentItemId)       │
  │    if (sourceItem 存在):                                  │
  │      冲销行.accountingTotalValue     = sourceItem × (-1) │
  │      冲销行.baseCurAccountingTotalValue = sourceItem × (-1)│
  │      冲销行.addedValue              = sourceItem × (-1)  │
  │      冲销行.baseCurAddedValue       = sourceItem × (-1)  │
  │      冲销行.metalValue              = sourceItem × (-1)  │
  │      冲销行.baseCurMetalValue       = sourceItem × (-1)  │
  └─────────────────────────────────────────────────────────┘
```

**与评估表的冲销处理对比**：

| 维度 | 库存价值报表 | 库存价值评估表 |
|------|------------|-------------|
| 冲销分类 | 按 `accountingTotalValue ≈ 0` 筛选 | 按 `offsetFlag = "Y"` 筛选 |
| 原始单据获取 | 递归调用自身 | 再查一次 Frame SQL |
| 取反字段数 | 6 个（accValue, addedValue, metalValue + 本位币） | ~15 个（含关联/未关联数量均价、CD金额等） |
| 自身数量取反 | 不做（SQL中已处理） | 做（quantity, deliveryInQuantity 等） |

## 五、发票查询 SQL 详解（listInvoiceInfo）

```sql
SELECT
    di.id document_items_id,
    di.quantity product_quantity,                    -- 入库数量
    IFNULL(id.excl_tax_amount, 0) excl_tax_amount,   -- 不含税金额
    IFNULL(id.base_currency_excl_tax_amount, 0) base_currency_excl_tax_amount,
    IFNULL(id.quantity, 0) quantity,                  -- 开票数量
    id.invoice_stage,                                 -- 发票阶段（final=最终）
    id.cd_valuation_type,                             -- CD类型（区分金属价/附加价）
    di.quantity - IFNULL(id.quantity, 0) unmatchQuantity  -- 未匹配数量
FROM document_items di
LEFT JOIN (
    -- 发票汇总：按 document_items_id + cd_valuation_type 分组
    SELECT
        id.document_items_id,
        i.cd_valuation_type,
        SUM(id.excl_tax_amount) excl_tax_amount,
        SUM(id.base_currency_excl_tax_amount) base_currency_excl_tax_amount,
        SUM(id.quantity) quantity,
        GROUP_CONCAT(DISTINCT id.invoice_stage) invoice_stage
    FROM invoice_documents id
    LEFT JOIN invoice i ON id.invoice_id = i.id
    WHERE i.gzstatus IN (3, 4, 5, 9)          -- 已审核/已确认等状态
        AND i.sap_push_status = 2              -- 已推送SAP
        AND i.invoice_type = 'DomesticInvoiceMaterial'  -- 国内材料发票
        AND i.id NOT IN (
            -- 排除已被冲销发票抵消的原始发票
            SELECT original_id FROM invoice
            WHERE invoice_type = 'DomesticInvoiceMaterialOffset'
                AND sap_push_status = 2
                AND post_date <= #{lastDate}
        )
        AND i.post_date <= #{lastDate}         -- 不超过查询月末
    GROUP BY id.document_items_id, i.cd_valuation_type
) id ON id.document_items_id = di.id
```

**关键过滤条件**：

| 条件 | 含义 |
|------|------|
| `gzstatus IN (3,4,5,9)` | 发票已审核/已确认/已推送 |
| `sap_push_status = 2` | 发票已推送SAP |
| `invoice_type = 'DomesticInvoiceMaterial'` | 国内材料发票（非冲销） |
| `NOT IN (冲销发票的original_id)` | 排除已被冲销抵消的发票 |
| `post_date <= lastDate` | 不超过查询会计月的月末 |

## 七、与评估表 fillEvaluationInfo 的核心差异

| 维度 | 库存价值报表 (本报表) | 库存价值评估表 (fillEvaluationInfo) |
|------|---------------------|----------------------------------|
| **记账金额来源** | SQL 从月结快照表直接取 | Java 层按定价类型实时计算 |
| **附加价来源** | SQL 从月结快照表直接取 | Java 层按 Z002/Z003 + 定价类型计算 |
| **金属价计算** | `accValue×(未匹配/仓库) + (发票-addedValue)` | `accValue - addedValue`（简单减法） |
| **finalPrice** | 不计算 | 按固定价/均价/点价三种方式计算 |
| **关联/未关联拆分** | 不展示 | 详细展示 relatedQty/unrelatedQty/均价 |
| **CD金额** | 不展示 | 详细展示 receivableCDAmount |
| **SCO价格** | 不使用 | 未定价时使用 SCO 价格估算金属价 |
| **冲销处理** | 零金额时递归查原始单据取反 | 所有冲销行统一从 normalResultMap 取反 |
| **计算行数** | ~230 行 Java 代码 | ~1000 行 Java 代码 |
| **复杂度** | 中等 | 极高 |

**简单理解**：
- **本报表** = "读快照 + 补发票 + 算金属价"，是对月结执行结果的**二次加工展示**
- **评估表** = "从源数据重新算一遍"，是**独立的完整估值引擎**
