# 月底净库存估值表 — 调用链梳理

> **业务含义**：汇总采购+销售+库存多源数据，进行金属成分拆分和 LME 估值计算，生成月底净库存的估值报表。只读报表，不落库。

---

## 一、调用链路图

```mermaid
flowchart TB

    B --> C["数据收集阶段"]
    C --> C1["采购库存数据<br/>purchaseSalesSnapshotDetailMapper"]
    C --> C2["销售Engagement数据<br/>salesEngagamentAdjustdifferenceDetailsService"]
    C --> C3["SAP增量数据<br/>sapMetalCompositionInventoryService"]

    C --> C6["Greenlist价格<br/>greenlist_price_snapshot"]
    
    B --> D["计算阶段"]
    D --> D1["金属成分拆分<br/>按机构+商品+工厂"]
    D --> D2["LME估值计算<br/>金属量 × LME价格 × 汇率"]
    D --> D3["净库存汇总<br/>采购-销售+库存调整"]

```

## 二、数据收集阶段（核心）

### 2.1 多源数据加载

月底净库存估值需要从多个数据源汇总：

| 数据源 | 方法/来源 | 用途 |
|--------|----------|------|
| 采购库存 | `purchaseSalesSnapshotDetailMapper` | 已定价未入库的采购量+金额 |
| 销售Engagement | `salesEngagamentAdjustdifferenceDetailsService` | 已定价未开票的销售量+金额 |
| SAP增量 | `sapMetalCompositionInventoryService` | B/C/D/E/H/F/A 类型的库存变动 |
| LME价格 | `forward_price` 表 | Cash/Lowest 结算价（前3交易日） |
| USD-EUR汇率 | `forward_price` 表 | Bloomberg USD-EUR 汇率 |
| 金属成分 | `product_specification` | Cu/Ni/Sn/Al/Zn/Pb/Yield 占比 |
| Greenlist价格 | `greenlist_price_snapshot` | 已执行的 Greenlist 快照数据 |
| 商品大类 | `product_category` | Z001/Z002/Z003 分类 |
| 工厂映射 | `abutment_config_details` | 机构ID→工厂代码 |

### 2.2 数据过滤条件

- **时间范围**：截至请求的会计月末
- **业务机构**：按 `legalEntityId` 过滤
- **业务板块**：排除 RB/RS 板块
- **合同类型**：排除短期合同（`contract_type != 'ShortTerm'`）

## 三、计算逻辑

### 3.1 金属成分拆分

与采购/销售快照逻辑一致：
- **原材料（Z001）**：取自身 `product_specification`
- **半成品（Z002）/成品/Alloy（Z003）**：取顶层父商品的 `product_specification`
- **工厂维度过滤**：按 `category` 匹配工厂代码

```java
yieldValue = Yield折率
yieldMutQuantity = quantity × yieldValue

for each metal (Cu/Ni/Sn/Al/Zn/Pb):
    metalKg = metalPct × yieldMutQuantity
```

### 3.2 LME 估值计算

```java
// 取前3交易日 LME 结算价（Cash 或 Lowest，取决于 family）
lmePrice = forwardPriceMap.get(curveId)
lmePriceEur = lmePrice × usdEurExchangeRate  // USD → EUR

for each metal:
    metalValueEur = metalKg × lmePriceEur
```

### 3.3 净库存汇总

```
净库存量 = 采购已定价量 - 销售已定价量 + SAP库存调整
净库存估值 = Σ(各金属 metalValueEur) + Greenlist Adder 调整
```

## 四、响应结构 — 字段与计算公式

**返回类型**：`List<EomCommittedStockValuationRes>`

| 字段 | 注释名 | 计算公式 | 说明 |
|------|--------|---------|------|
| `legalEntityId` | 业务机构ID | 直接取值 | — |
| `legalEntityName` | 业务机构全称 | 直接取值 | — |
| `purEngVal` | 采购净库存价值 (Pur Eng Val) | 采购已定价未入库的估值汇总 | 来自采购快照数据 |
| `salEngVal` | 销售净库存价值 (Sal Eng Val) | 销售已定价未开票的估值汇总 | 来自销售快照数据 |
| `lmeLongVal` | LME多头价值 (LME Long Val) | LME 多头头寸 × LME 价格 | 采购方向的 LME 估值 |
| `lmeShortVal` | LME空头价值 (LME Short Val) | LME 空头头寸 × LME 价格 | 销售方向的 LME 估值 |
| `saleEngRmVal` | 原材料净库存价值 (Sale Eng Rm Val) | 原材料已定价未开票的估值 | 来自销售快照中 Z001 类商品 |
| `valAccrual` | 估值 (Val Accrual) | 手工录入的估值调整值 | — |
| `smallHedgeVal` | 小额对冲价值 (Small Hedge Val) | 手工录入的小额对冲值 | 通过 `saveSmallHedge()` 保存 |
| `totalValue` | 总价值 (Total Value) | `purEngVal + salEngVal + lmeLongVal + lmeShortVal + saleEngRmVal + valAccrual + smallHedgeVal` | 各分项之和 |
| `currencyName` | 币种 | 固定 "EUR" | 欧元 |
| `currencyId` | 币种ID | 固定值 | 欧元 |

**计算公式汇总**：

```
Total Value = Pur Eng Val + Sal Eng Val + LME Long Val + LME Short Val 
            + Sale Eng Rm Val + Val Accrual + Small Hedge Val
```

## 六、重要业务备注

1. **只读报表**：不落库，每次查询实时计算
2. **多源数据汇总**：采购+销售+SAP 三方数据合并
3. **与快照的关系**：计算逻辑与采购/销售快照(①②)的金属拆分一致，但本报表是实时查询而非快照落库
4. **Greenlist 依赖**：需要先执行 Greenlist 快照(⑤)才有价格数据可用
5. **Small Hedge Val**：支持手工录入小额对冲估值，与系统计算值并存
