## 一、报表概述

### 这是什么报表？

这是一个**库存价值评估明细表**（Detail Entries Value Evaluation），属于大宗商品贸易/仓储管理系统中的**月末（EOM）库存估值报表**。

### 统计维度

| 维度 | 对应字段 |
|------|---------|
| **时间** | 会计日、过账日期、货权转移日期 |
| **单据** | 单据号、单据类型、单据行号 |
| **合同** | 合同号、合同行号、SAP订单号 |
| **交易对手** | 交易对家名称 |
| **组织** | 业务机构（Legal Entity）、业务部门、业务板块 |
| **仓储** | 仓库名称、工厂 |
| **商品** | 商品名、合金、批次号、父商品 |
| **币种** | 结算币种、本位币种 |

### 核心计算内容

每条记录计算并展示：

- **数量类**：入库数量、冲销数量、已入库库存数量、已开票数量、待开票数量
- **金额类**：记账金额（金属价 + 附加价）、开票金额、暂估价
- **关联类**：已关联数量/均价、未关联数量/均价、待收 Credit/Debit 金额
- **本位币折算**：上述金额均同时计算本位币版本（通过汇率转换）

## 二、`listDetailEntrisValueEvaluation` 方法分析

### 方法整体职责

该方法是报表的**入口方法**，负责三件事：
1. 从数据库查出骨架数据
2. 处理冲销逻辑（找到原始单据 → 统一计算 → 冲销取反）
3. 调用 `fillEvaluationInfo` 完成金额计算

### 两个核心列表的作用

```
normalResults  → "计算工作台"：包含所有需要参与金额计算的记录
offsetResults  → "取反清单"：仅包含冲销单据，计算完成后统一做金额取反
```

> **核心问题**：冲销单据本身不携带完整的金额信息，它引用了一条原始单据（`sourceDocumentItemId`），
> 金额必须从原始单据的计算结果中复制并取反。因此需要两个列表分别管理。

### 完整处理流程

```
═══════════════════════════════════════════════════════════════
  Step 1：数据库查询骨架数据
═══════════════════════════════════════════════════════════════

  results = baseMapper.listDetailEntrisValueEvaluationFrame(query)

  假设查询返回 5 条记录：
  ┌──────────────────────────────────────────────────────────┐
  │ id=101  正常单据  offsetFlag=N  sourceDocumentItemId=null │
  │ id=102  正常单据  offsetFlag=N  sourceDocumentItemId=null │
  │ id=103  冲销单据  offsetFlag=Y  sourceDocumentItemId=101  │  ← 冲销 id=101
  │ id=104  冲销单据  offsetFlag=Y  sourceDocumentItemId=201  │  ← 冲销 id=201（不在当前结果中！）
  │ id=105  正常单据  offsetFlag=N  sourceDocumentItemId=null │
  └──────────────────────────────────────────────────────────┘


═══════════════════════════════════════════════════════════════
  Step 2：分类到两个列表
═══════════════════════════════════════════════════════════════

  遍历 results，按 offsetFlag 分流：

              ┌──────────────────────────────────┐
              │        results (5条记录)          │
              └──────────────┬───────────────────┘
                             │
                    offsetFlag == "Y" ?
                    ┌────────┴────────┐
                    │ 是               │ 否
                    ▼                 ▼
          ┌─────────────────┐  ┌─────────────────┐
          │  offsetResults   │  │  normalResults   │
          │  (仅冲销单据)     │  │  (所有记录)       │
          │                  │  │                  │
          │  id=103 (→101)   │  │  id=101          │
          │  id=104 (→201)   │  │  id=102          │
          └─────────────────┘  │  id=103          │
                               │  id=104          │
          同时收集：             │  id=105          │
          sourceDocumentItemId  └─────────────────┘
          List = [101, 201]

  ⚠ 注意：冲销单据（103、104）同时存在于两个列表中


═══════════════════════════════════════════════════════════════
  Step 3：回填缺失的原始单据
═══════════════════════════════════════════════════════════════

  问题：id=104 冲销的原始单据 id=201 不在当前查询结果中
        → 如果不补回来，后面取反时找不到数据源

  解决：用 sourceDocumentItemIdList = [101, 201] 再查一次数据库

          sourceResults = baseMapper.listDetailEntrisValueEvaluationFrame(sourceQuery)
          → 查到 id=201（id=101 已存在，去重后不重复添加）

          normalResults.addAll(sourceResults)

  补回后 normalResults：
  ┌─────────────────────────────────────────┐
  │ id=101  id=102  id=103  id=104  id=105  │  ← 原始5条
  │ id=201                                   │  ← 新补回的原始单据
  └─────────────────────────────────────────┘


═══════════════════════════════════════════════════════════════
  Step 4：统一计算所有金额（核心步骤）
═══════════════════════════════════════════════════════════════

  fillEvaluationInfo(accountingDate, normalResults)
  ┌─────────────────────────────────────────────────────────┐
  │ 对 normalResults 中的每一条记录（包括补回的201），         │
  │ 统一计算：finalPrice → accountingTotalValue              │
  │         → addedValue → metalValue → CD调整 → ...        │
  │                                                          │
  │ 计算完成后构建 Map：                                      │
  │ normalResultMap = { id → 完整计算结果 }                   │
  └─────────────────────────────────────────────────────────┘

  同时回填冲销数量：
  selectDocItemOffsetQuantity → 每条记录的 offsetQuantity


═══════════════════════════════════════════════════════════════
  Step 5：冲销单据取反（offsetResults 专用）
═══════════════════════════════════════════════════════════════

  遍历 offsetResults 中的每条冲销单据 a：

  ┌─────────────────────────────────────────────────────────┐
  │ 5a. 自身数量取反                                         │
  │     a.quantity           = a.quantity × (-1)            │
  │     a.deliveryInQuantity = a.deliveryInQuantity × (-1)  │
  │     a.deliveryInStockQuantity = ... × (-1)              │
  │     a.offsetQuantity     = 0                            │
  ├─────────────────────────────────────────────────────────┤
  │ 5b. 找到对应的原始单据 b                                  │
  │     b = normalResultMap.get(a.sourceDocumentItemId)     │
  │     例：a=id103 → b=id101                               │
  │         a=id104 → b=id201                               │
  │     如果找不到 b → 跳过（continue）                       │
  ├─────────────────────────────────────────────────────────┤
  │ 5c. 从 b 复制金额并取反                                  │
  │     a.invoicedQuantity       = b.invoicedQuantity × (-1)│
  │     a.uninvoicedQuantity     = b.uninvoicedQuantity × (-1)│
  │     a.accountingTotalValue   = b.accountingTotalValue × (-1)│
  │     a.addedValue             = b.addedValue × (-1)       │
  │     a.metalValue             = b.metalValue × (-1)       │
  │     a.taxIncInvoiceAmount    = b.taxIncInvoiceAmount × (-1)│
  │     a.baseCurXxx（所有本位币字段）= b.baseCurXxx × (-1)  │
  │     a.relatedQuantity        = b.relatedQuantity × (-1)  │
  │     a.unrelatedQuantity      = b.unrelatedQuantity × (-1)│
  │     a.receivableCDAmount     = b.receivableCDAmount × (-1)│
  │     ...（共约15个字段取反）                               │
  └─────────────────────────────────────────────────────────┘


═══════════════════════════════════════════════════════════════
  Step 6：返回 results（原始列表，包含正常+冲销）
═══════════════════════════════════════════════════════════════

  return results;
  （results 中的对象引用与 normalResults/offsetResults 共享，
    修改已生效，无需合并）
```

### 数据流转全景图

```
  DB查询 ──→ results ──→ 分类 ──→ normalResults（全部记录）
    │                            + offsetResults（仅冲销）
    │                                │
    │                                │ 收集 sourceDocumentItemIdList
    │                                ▼
    │                          再查DB补回缺失的原始单据
    │                                │
    │                                ▼
    │                     normalResults.addAll(补回的单据)
    │                                │
    │                                ▼
    │                     fillEvaluationInfo(normalResults)
    │                     ┌──────────────────────────────┐
    │                     │ 统一计算所有金额字段           │
    │                     │ 构建 normalResultMap          │
    │                     │ 回填 offsetQuantity           │
    │                     └──────────────┬───────────────┘
    │                                    │
    │                                    ▼
    │                     遍历 offsetResults：
    │                     从 normalResultMap 找到原始单据 b
    │                     复制 b 的金额 → 全部 ×(-1)
    │                                    │
    │                                    ▼
    └──────────────────────────→ return results
```

### 为什么需要两个列表？

| 问题 | 解答 |
|------|------|
| 为什么不直接在 results 上计算？ | 因为冲销单据的金额依赖原始单据的计算结果，必须先算完原始单据才能处理冲销 |
| 为什么 normalResults 包含冲销单据？ | 冲销单据自身的基础字段（如商品信息、合同信息）也需要参与 `fillEvaluationInfo` 的部分计算 |
| 为什么 offsetResults 是单独的？ | 冲销取反是最后一步，必须在所有正常计算完成后才能执行，需要单独标记哪些记录需要取反 |
| 补回的原始单据（如id=201）会出现在返回结果中吗？ | 不会。它只存在于 `normalResults` 中参与计算，最终返回的是 `results`（原始查询结果） |

## 三、`fillEvaluationInfo` 方法分析（核心计算引擎）

### 方法定位

这是库存价值评估报表的**核心计算引擎**，负责对从数据库查出的"骨架数据"进行**金额层面的完整赋值**。所有关键金额字段（记账金额、金属价、附加价、开票金额、暂估价、CD金额等）都在这里计算。

---

### 【总】整体结构（三大阶段）

```
阶段一（617-647行）  收集ID → 为批量查询做准备
阶段二（649-817行）  批量加载关联数据（9大类）
阶段三（819-1607行） 逐条记录计算所有金额字段（11步）
```

数据流转全景：

```

```

### 【分】阶段二：批量加载9类关联数据（649-817行）

| # | 数据 | 查询条件 | 用途 | 分组方式 |
|---|------|---------|------|---------|
| ① | `MovementPrice`（定价明细） | physicalDealLineId + priced=1 + 日期≤会计日 | 计算最终价、附加价 | 按 pdLineId 分组 |
| ② | `PriceTriggering`（点价明细） | physicalDealLineId + 日期≤会计日 | 点价类型的关联/未关联计算 | 按 pdLineId 分组 |

#### 3.1 Step①② 汇率计算 & 暂估价（839-930行）

#### 3.2 Step③ 最终价 finalPrice（932-1073行）

finalPrice 是后续计算记账金额的基础单价，按**是否有定价记录**和**计价类型**走不同算法。

```
              ┌─────────────────────────────┐
              │ 合同商品行是否有定价记录？     │
              │ (MovementPrice 列表是否非空)  │
              └──────────┬──────────────────┘
                         │
            ┌────────────┴────────────┐
            │ 无定价记录               │ 有定价记录
            ▼                         ▼
  finalPrice = estimatedPrice     ┌──────────────────────────┐
  (暂估价，来自入库单据原始数据)     │ 计价类型 pricingType？    │
                                  └──────┬───────────────────┘
                                         │
              ┌──────────────────────────┼──────────────────────────┐
              │ BasicFixedPrice          │ BasicAveragePrice        │ BasicTriggeredPrice
              │ (固定价)                  │ (均价)                    │ (点价)
              ▼                          ▼                          ▼
  取最新一条 MovementPrice     加权平均计算：                 分"已关联"和"未关联"两部分：
  的 settlementNetPrice       Σ(单价×数量) / Σ数量          ┌─────────────────────────┐
  作为 finalPrice             作为 finalPrice               │已关联部分：               │
                                                            │ relaAmount = Σ(点价结算价  │
  若为0则回退取estimatedPrice   若为0则回退取estimatedPrice   │   × 关联数量)             │
                                                            │                          │
                                                            │未关联部分：               │
                                                            │ unRelaPrice = Σ(点价结算价 │
                                                            │   × 未关联数量)           │
                                                            │   / Σ未关联数量           │
                                                            │                          │
                                                            │finalPrice =              │
                                                            │ (数量-relaQty)×unRelaPrice│
                                                            │ + relaAmount) / 数量      │
                                                            └─────────────────────────┘
              │                          │                          │
              └──────────────────────────┼──────────────────────────┘
                                         ▼
                                  得到 finalPrice
                                  (用于后续记账金额计算)
```

**三种计价类型的详细逻辑**：

**固定价（BasicFixedPrice）**：
```
  遍历该合同行下所有 MovementPrice：
    取 createdTime 最新 且 settlementNetPrice 非空 的一条
    finalPrice = 该条的 settlementNetPrice
    baseCurFinalPrice = 该条的 settlementNetPriceBaseCur

  若 finalPrice == 0 → 回退取 estimatedPrice
```

**均价（BasicAveragePrice）**：
```
  遍历该合同行下所有 MovementPrice：
    累加：finalQuantity += quantity
          finalAmount   += settlementNetPrice × quantity
          finalAmountBaseCur += settlementNetPriceBaseCur × quantity
    （跳过 settlementNetPrice == 0 的记录）

  finalPrice = finalAmount / finalQuantity（精度9位）
  baseCurFinalPrice = finalAmountBaseCur / finalQuantity

  若 finalPrice == 0 → 回退取 estimatedPrice
```

**点价（BasicTriggeredPrice）**：
```
  已关联部分（通过 ptRelaGroupByDi 按 docItemId 查找）：
  ┌──────────────────────────────────────────────────────┐
  │ 遍历该入库明细关联的点价-仓库关联记录：                  │
  │   relaQuantity += 关联数量                             │
  │   relaAmount   += 点价结算价 × 关联数量                 │
  │                 (无结算价则用暂估价)                    │
  │   baseCurRelaAmount += 本币结算价 × 关联数量            │
  └──────────────────────────────────────────────────────┘

  未关联部分（通过 ptRelaGroupByPt 按点价ID查找）：
  ┌──────────────────────────────────────────────────────┐
  │ 遍历该合同行下所有点价记录：                            │
  │   ptQuantity = 点价数量 - Σ(该点价的关联数量)           │
  │   pdLineUnrelatedQuantity += ptQuantity               │
  │   unRelaAmount += ptQuantity × 点价结算价              │
  │                (无结算价则用暂估价)                     │
  │   baseCurUnRelaAmount += ptQuantity × 本币结算价       │
  │                                                       │
  │ unRelaPrice = unRelaAmount / pdLineUnrelatedQuantity  │
  │ (若未关联数量=0 → unRelaPrice = estimatedPrice)       │
  └──────────────────────────────────────────────────────┘

  finalPrice = ((数量 - relaQuantity) × unRelaPrice + relaAmount) / 数量
```

#### 3.3 Step④ 记账金额 accountingTotalValue（1076-1129行）

记账金额是报表的核心金额字段，计算逻辑按**开票状态**分流：

```
              ┌─────────────────────────────────┐
              │ 开票状态判断：                     │
              │ 已开票数量>0 且 待开票数量≤0       │
              │ 或 invoiceStage = "Final"        │
              └──────────┬──────────────────────┘
                         │
            ┌────────────┴────────────┐
            │ 完全开票                 │ 部分开票 / 未开票
            ▼                         ▼
┌──────────────────────┐   ┌──────────────────────────────────┐
│accountingTotalValue  │   │ 计价类型 pricingType？             │
│ = taxIncInvoiceAmount│   └──────┬───────────────────────────┘
│ (直接取发票不含税金额) │          │
│                      │   ┌──────┴──────────────────────────┐
│baseCurAccountingTotal│   │ BasicTriggeredPrice(点价)        │ 其他(固定价/均价)
│ = 发票不含税本币金额   │   ▼                                ▼
└──────────────────────┘   ┌─────────────────────┐  ┌────────────────────┐
                           │ invoicedQty 与       │  │accountingValue =   │
                           │ relatedQty 比较？     │  │ (数量-已开票数量)    │
                           └──────┬──────────────┘  │ × finalPrice        │
                                  │                  │ + taxIncInvoiceAmt  │
                    ┌─────────────┴────────────┐     └────────────────────┘
                    │ relatedQty < invoicedQty │     │ relatedQty ≥ invoicedQty
                    ▼                          ▼
          ┌────────────────────┐    ┌────────────────────────────┐
          │ 未关联部分覆盖未开票 │    │ 关联部分按比例覆盖未开票      │
          │                    │    │                             │
          │ value =            │    │ amount1 = (relaQty          │
          │ (数量-invoicedQty)  │    │   - invoicedQty)            │
          │ × unrelatedAvgPrice│    │   × (relaAmount/relaQty)    │
          │ + taxIncInvoiceAmt │    │                             │
          └────────────────────┘    │ amount2 = (数量-relaQty)     │
                                    │   × unrelatedAvgPrice        │
                                    │                             │
                                    │ value = amount1+amount2      │
                                    │       + taxIncInvoiceAmt     │
                                    └────────────────────────────┘
                    │                          │             │
                    └──────────────────────────┼─────────────┘
                                               ▼
                                    得到 accountingTotalValue
                                    (用于后续 metalValue 计算)
```

**各场景解读**：

| 场景 | 公式 | 含义 |
|------|------|------|
| **完全开票** | `accountingValue = taxIncInvoiceAmount` | 发票金额即记账金额 |
| **部分/未开票 + 固定价/均价** | `(数量-已开票数量) × finalPrice + 已开票金额` | 未开票部分按最终价估算 |
| **部分/未开票 + 点价 + 关联<开票** | `(数量-已开票数量) × 未关联均价 + 已开票金额` | 未开票部分用未关联均价 |
| **部分/未开票 + 点价 + 关联≥开票** | `(关联-开票)×关联均价 + (数量-关联)×未关联均价 + 已开票金额` | 未开票部分拆关联/未关联两段 |

#### 3.4 Step⑤⑥ 附加价 addedValue & 金属价 metalValue（1131-1317行）★重点

这是整个方法最复杂的部分，经过**三层判断**：

```
  ┌──────────────────────────────────────────────────────────────────┐
  │                     第一层：商品财务属性                           │
  │                                                                  │
  │  Z001(原材料) ──→ addedValue=0, metalValue=accountingTotalValue  │
  │                                                                  │
  │  非Z001 ──→ 进入第二层                                            │
  └──────────────────────────────────────────────────────────────────┘
                              │
                              ▼
  ┌──────────────────────────────────────────────────────────────────┐
  │                     第二层：是否有定价记录(priced)                  │
  │                                                                  │
  │  已定价 ──→ 先算 addedValue → 反推 metalValue                     │
  │  未定价 ──→ 先算 metalValue(SCO价格) → 反推 addedValue             │
  └──────────────────────────────────────────────────────────────────┘
                              │
                              ▼
  ┌──────────────────────────────────────────────────────────────────┐
  │                     第三层：CD Note 调整                          │
  │                                                                  │
  │  有附加价CD Note ──→ metalValue 和 addedValue 内部再分配           │
  │  无 ──→ 不调整                                                   │
  └──────────────────────────────────────────────────────────────────┘
```

##### 第一层：原材料 Z001（1132-1138行）

```
  商品财务属性 accountingGroup == "Z001"：

    addedValue = 0              ← 原材料没有加工附加值
    metalValue = accountingTotalValue  ← 全部价值都是金属价值
    baseCurAddedValue = 0
    baseCurMetalValue = baseCurAccountingTotalValue
```

##### 第二层-路径A：已定价（priced=true）（1141-1281行）

先按计价类型计算 `addedValue`，再反推 `metalValue`。

**固定价/均价的 addedValue 计算**：
```
  遍历该合同行下所有 MovementPrice：
  ┌──────────────────────────────────────────────────────┐
  │ 累加：mpQuantity      += quantity                     │
  │       mpAddedValue    += additionalPrice × quantity   │
  │       mpAddedValueBaseCur += additionalPriceBaseCur × quantity │
  │                                                       │
  │ 同时累加简单平均（兜底用）：                              │
  │       mpAverageAddedPrice += additionalPrice          │
  │       mpAverageAddedPriceSize++                       │
  └──────────────────────────────────────────────────────┘

  if mpQuantity == 0:
      addedPrice = mpAverageAddedPrice / size     ← 简单平均兜底
  else:
      addedPrice = mpAddedValue / mpQuantity      ← 加权平均

  addedValue = addedPrice × 数量 × KG转换率
  baseCurAddedValue = addedPriceBaseCur × 数量 × KG转换率

  → 然后反推：metalValue = accountingTotalValue - addedValue
```

**点价的 addedValue 计算**：
```
  关联部分（通过 ptRelaGroupByDi 按 docItemId 查找）：
  ┌──────────────────────────────────────────────────────┐
  │ 遍历该入库明细关联的点价-仓库关联记录：                  │
  │   relaTriQuantity   += 关联数量                       │
  │   relaTriAddedAmount += MovementPrice.additionalPrice │
  │                          × 关联数量                    │
  └──────────────────────────────────────────────────────┘

  未关联部分（通过 ptRelaGroupByPt 按点价ID查找）：
  ┌──────────────────────────────────────────────────────┐
  │ 遍历该合同行下所有点价记录：                            │
  │   ptQuantity = 点价数量 - Σ(该点价的关联数量)           │
  │   unRelaTriQuantity   += ptQuantity                   │
  │   unRelaTriAddedAmount += MovementPrice.additionalPrice│
  │                           × ptQuantity                 │
  │                                                       │
  │ 特殊情况（未定价兜底）：                                │
  │   若 unRelaTriAddedAmount == 0 且有暂估价：             │
  │     scoPrice = getScoPrice(productId, contractDate,   │
  │              quantityUnitId, settleCurrencyId,        │
  │              legalEntityId)                           │
  │     unRelaTriAddedPrice = estimatedPrice - scoPrice   │
  │     ↑ 暂估价减去SCO金属价 = 附加价单价                  │
  │   否则：                                               │
  │     unRelaTriAddedPrice = unRelaTriAddedAmount        │
  │                         / unRelaTriQuantity            │
  └──────────────────────────────────────────────────────┘

  最终：
  unrelaQuantity = 数量 - relaTriQuantity
  addedValue = relaTriAddedAmount + unrelaQuantity × unRelaTriAddedPrice
  baseCurAddedValue = relaTriAddedAmountBaseCur + unrelaQuantity × unRelaTriAddedPriceBaseCur

  → 然后反推：metalValue = accountingTotalValue - addedValue
```

##### 第二层-路径B：未定价（priced=false）（1282-1317行）

没有定价记录时，先通过 SCO 价格算 `metalValue`，再反推 `addedValue`。

```
  ┌─────────────────────────────────────────────────────────────┐
  │ Step 1: 获取 SCO 价格                                       │
  │   scoPrice = riskUtil.getScoPrice(productId, contractDate,  │
  │                                       legalEntityId)        │
  │   scoPriceBD = scoPrice.getMarketPriceValue()               │
  │                                                             │
  │ Step 2: 单位转换（SCO价格单位 → KG）                         │
  │   scoToKgConversion = getUnitConversion(scoUnit, kgUnit,    │
  │                                         productId)          │
  │   scoPriceBD = scoPriceBD / scoToKgConversion               │
  │                                                             │
  │ Step 3: 币种转换（SCO币种 → 结算币种）                       │
  │   scoCurrencyToSettleExchange = getExchangeRate(            │
  │       scoCurrencyId, settlementCurrencyId, contractDate)    │
  │   scoPriceBD = scoPriceBD × scoCurrencyToSettleExchange     │
  │                                                             │
  │ Step 4: 结算币种 → 本位币                                   │
  │   scoPriceBaseCurBD = scoPriceBD × settleToBaseExchangeRate │
  │                                                             │
  │ Step 5: 计算金属价                                          │
  │   metalValue = scoPriceBD × quantity                        │
  │   baseCurMetalValue = scoPriceBaseCurBD × quantity          │
  │                                                             │
  │ Step 6: 反推附加价（注意方向与路径A相反！）                    │
  │   addedValue = accountingTotalValue - metalValue            │
  │   baseCurAddedValue = baseCurAccountingTotalValue           │
  │                     - baseCurMetalValue                     │
  └─────────────────────────────────────────────────────────────┘
```

##### 第三层：CD Note 调整（1320-1338行）

如果该入库明细有**附加价类型的 CD Note 发票**（`CdValuationType = ADDED_VALUE`），对金属价和附加价做再分配：

```
              ┌─────────────────────────────────┐
              │ 是否存在 CdValuationType         │
              │ = ADDED_VALUE 的 CD Note 发票？  │
              └──────────┬──────────────────────┘
                         │
                ┌────────┴────────┐
                │ 有               │ 无
                ▼                 ▼
  ┌──────────────────────────┐   (不调整)
  │cdAddedValue =            │
  │ CD Note发票不含税金额     │
  │                          │
  │addedValue += cdAddedValue│  ← 附加价吸收CD金额
  │metalValue -= cdAddedValue│  ← 金属价扣减CD金额
  │                          │
  │本位币按比例调整：          │
  │baseCurAddedValue =       │
  │  (addedValue+cdAddedValue)│
  │  / addedValue             │
  │  × baseCurAddedValue      │
  │                          │
  │baseCurMetalValue =       │
  │  (metalValue-cdAddedValue)│
  │  / metalValue             │
  │  × baseCurMetalValue      │
  │                          │
  │(记账总额不变，内部再分配)   │
  └──────────────────────────┘
```

                    │  商品财务属性是什么？      │
                    └────────┬────────────────┘
                             │
              ┌──────────────┴──────────────┐
              │ Z001(原材料)                 │ 非Z001(半成品/产成品)
              ▼                             ▼

##### 推导方向总结

| 场景 | 推导方向 | 原因 |
|------|----------|------|
| **原材料 Z001** | `metalValue = accountingTotalValue`，`addedValue = 0` | 原材料无加工附加值 |
| **非原材料 + 已定价** | 先算 `addedValue` → 反推 `metalValue` | 有 MovementPrice 的 `additionalPrice` 字段可直接算附加价 |
| **非原材料 + 未定价** | 先算 `metalValue`（SCO价格×数量）→ 反推 `addedValue` | 没有定价记录，只能用市场参考价估算金属部分 |
| **CD Note 调整** | 在已有结果上做 `metalValue → addedValue` 的转移 | CD Note 的附加价部分需要从金属价"搬"到附加价 |

#### 3.6 Step⑨ 待收Credit/Debit金额（1418-1496行）

待收CD金额 = 关联部分CD + 未关联部分CD，按开票状态和计价类型分别计算。

```
  ┌──────────────────────────────────────────────────────────────┐
  │ 前置判断                                                      │
  │                                                              │
  │ 合同已关闭？ ──→ 全部CD金额置0                                │
  │                                                              │
  │ 已开票 且 关联数量=0 且 未关联数量=0？                          │
  │          ──→ 全部CD金额置0（点价已全部定价并开票，无差异）       │
  │                                                              │
  │ 否则 → 进入下方计算                                           │
  └──────────────────────────────────────────────────────────────┘

  发票数量 = min(已入库数量, 已开票数量)

  ┌──────────────────────────────────────────────────────────────┐
  │ 关联部分 relatedReceivableCDAmount                            │
  │                                                              │
  │  发票数量=0 → 0                                               │
  │                                                              │
  │  均价：                                                       │
  │    = 已关联均价 × 发票数量 - 已开票金额                         │
  │                                                              │
  │  固定价/点价：                                                 │
  │    取 relaQty = min(发票数量, 关联数量)                         │
  │    = relaQty × 已关联均价                                     │
  │      - (relaQty / 发票数量) × 已开票金额                       │
  └──────────────────────────────────────────────────────────────┘

  ┌──────────────────────────────────────────────────────────────┐
  │ 未关联部分 unrelatedReceivableCDAmount                        │
  │                                                              │
  │  仅点价类型才计算（固定价/均价 = 0）                            │
  │                                                              │
  │  发票数量 > 关联数量？                                         │
  │    是：= (发票数量-关联数量) × 未关联均价                       │
  │        - (发票数量-关联数量)/发票数量 × 已开票金额               │
  │    否：= 0                                                    │
  └──────────────────────────────────────────────────────────────┘

  receivableCDAmount = relatedReceivableCDAmount
                     + unrelatedReceivableCDAmount
  baseCurReceivableCDAmount = 同上（本位币版本）
```

#### 3.8 Step⑪ 冲销数量取反 & 精度处理（1559-1606行）

```
  冲销数量取反：
    offsetQuantity = offsetQuantity × (-1)

  精度统一（全部 setScale(5, HALF_UP)）：
  ┌──────────────────────────────────────────────────────────────┐
  │ 数量类（5位）：                                                │

  │                                                              │

  │   addedValue, baseCurAddedValue,                              │
  │   metalValue, baseCurMetalValue,                              │
  │   taxIncInvoiceAmount, baseCurTaxIncInvoiceAmount,            │
  │   relatedAmount, baseCurRelatedAmount,                        │
  │   relatedReceivableCDAmount, unrelatedReceivableCDAmount,     │
  │   receivableCDAmount 及其本位币版本                            │
  │                                                              │
  │ 单价类（5位）：                                                │
  │   estimatedPrice, baseCurEstimatedPrice,                      │
  │   finalPrice, baseCurFinalPrice,                              │
  │   relatedAvgPrice, baseCurRelatedAvgPrice,                    │
  │   unrelatedAvgPrice, baseCurUnrelatedAvgPrice,                │

```
