  方法分析：listDetailEntrisValueEvaluation

  这是什么报表？

  这是一个库存价值评估明细表（Detail Entries Value
  Evaluation），属于大宗商品贸易/仓储管理系统中的月末（EOM）库存估值报表。

  统计维度

  从实体类字段和查询条件来看，报表按以下维度展示数据：

  ┌──────────┬──────────────────────────────────────────────┐
  │   维度   │                   对应字段                   │
  ├──────────┼──────────────────────────────────────────────┤
  │ 时间     │ 会计日、过账日期、货权转移日期               │
  ├──────────┼──────────────────────────────────────────────┤
  │ 单据     │ 单据号、单据类型、单据行号                   │
  ├──────────┼──────────────────────────────────────────────┤
  │ 合同     │ 合同号、合同行号、SAP订单号                  │
  ├──────────┼──────────────────────────────────────────────┤
  │ 交易对手 │ 交易对家名称                                 │
  ├──────────┼──────────────────────────────────────────────┤
  │ 组织     │ 业务机构（Legal Entity）、业务部门、业务板块 │
  ├──────────┼──────────────────────────────────────────────┤
  │ 仓储     │ 仓库名称、工厂                               │
  ├──────────┼──────────────────────────────────────────────┤
  │ 商品     │ 商品名、合金、批次号、父商品                 │
  ├──────────┼──────────────────────────────────────────────┤
  │ 币种     │ 结算币种、本位币种                           │
  └──────────┴──────────────────────────────────────────────┘

  核心计算内容

  每条记录计算并展示：
  - 数量类：入库数量、冲销数量、已入库库存数量、已开票数量、待开票数量
  - 金额类：记账金额（金属价 + 附加价）、开票金额、暂估价
  - 关联类：已关联数量/均价、未关联数量/均价、待收 Credit/Debit 金额
  - 本位币折算：上述金额均同时计算本位币版本（通过汇率转换）

  ---
  normalResults 和 offsetResults 的作用

  这是处理**冲销（Reversal/Offset）**逻辑的关键：

  normalResults  → 所有记录（包括正常单据 + 冲销单据），作为最终返回的主体
  offsetResults  → 仅冲销单据（offsetFlag="Y"），用于特殊处理

  具体流程：

  1. 分类（第541-547行）：遍历查询结果，所有记录都加入
  normalResults；如果是冲销单据（offsetFlag="Y"），额外加入
  offsetResults，并记录其 sourceDocumentItemId（被冲销的原始单据ID）。
  2. 回填原始单据（第549-558行）：冲销单据引用了原始单据，但原始单据可能不在当前
  查询范围内。所以用 sourceDocumentItemIdList 再查一次，把缺失的原始单据也加入
  normalResults。
  3. 统一计算（第562-580行）：对 normalResults 统一调用 fillEvaluationInfo
  计算金额、开票、关联等数据，并回填每条记录的冲销数量。
  4.
  冲销取反（第582-613行）：对冲销单据（offsetResults），从其对应的原始单据（通过
  sourceDocumentItemId 关联）复制金额数据后全部乘以 -1，包括：
    - 数量取反（入库数量、库存数量）
    - 金额取反（记账金额、附加价、金属价、开票金额）
    - 关联/未关联数量和均价取反
    - 待收 Credit/Debit 金额取反

  简单来说：normalResults 是用来统一计算估值数据的"工作台"，offsetResults
  是需要做金额取反处理的冲销记录子集。冲销单据的金额不能独立计算，必须找到它对应
  的原始单据，取原始单据的计算结果再取负值，确保冲销在报表中体现为"减少"效果。

  ★ 重点：MetalValue 的赋值逻辑（完整决策树）

  MetalValue 的计算经过三个层次的赋值，后一层会覆盖或修正前一层的值：

  第一层：按商品财务属性分流（1131行）

  商品财务属性 = ProductFinancialAttributes.accountingGroup

  情况A：原材料（Z001） — 第1132-1138行

  // 原材料没有附加价，金属价 = 记账金额
  addedValue = 0
  metalValue = accountingTotalValue        // 直接等于记账金额
  baseCurMetalValue = baseCurAccountingTotalValue

  ▎ 逻辑：原材料不涉及加工，全部价值都是金属价值，附加价为零。

  情况B：非原材料（半成品/产成品等） — 进入第1139行以后的复杂分支

  第二层：非原材料的 MetalValue 计算（1276-1317行）

  这里有一个关键标志位 priced（是否有定价记录，即 MovementPrice 是否存在）：

  路径B1：已定价（priced = true） — 第1276-1281行

  metalValue = accountingTotalValue - addedValue
  baseCurMetalValue = baseCurAccountingTotalValue - baseCurAddedValue

  ▎ 逻辑：记账金额 = 金属价 + 附加价，已知记账金额和附加价，反推金属价。

  其中 addedValue 的计算方式取决于计价类型：

  ┌───────────────────────┬─────────────────────────────────────────────────┐
  │       计价类型        │               AddedValue 计算方式               │
  ├───────────────────────┼─────────────────────────────────────────────────┤
  │ 固定价                │ 加权平均附加单价 × 数量 ×                       │
  │ BasicFixedPrice       │ KG转换率（1143-1193行）                         │
  ├───────────────────────┼─────────────────────────────────────────────────┤
  │ 均价                  │ 同上（1143-1193行）                             │
  │ BasicAveragePrice     │                                                 │
  ├───────────────────────┼─────────────────────────────────────────────────┤
  │ 点价                  │ 关联部分附加金额 + 未关联数量 ×                 │
  │ BasicTriggeredPrice   │ 未关联附加均价（1194-1273行）                   │
  └───────────────────────┴─────────────────────────────────────────────────┘

  路径B2：未定价（priced = false） — 第1282-1317行

  // 金属价使用合同签订日期的 SCO 价格（Scorpro Price）
  scoPrice = riskUtil.getScoPrice(productId, contractDate, legalEntityId)

  // 单位转换：SCO价格单位 → KG
  scoPricePerKg = scoPrice / scoToKgConversion

  // 币种转换：SCO币种 → 结算币种
  scoPriceInSettleCur = scoPricePerKg × scoCurrencyToSettleExchange

  // 结算币种 → 本位币
  scoPriceInBaseCur = scoPriceInSettleCur × settleToBaseExchangeRate

  // 最终赋值
  metalValue = scoPriceInSettleCur × quantity
  baseCurMetalValue = scoPriceInBaseCur × quantity

  // 反推附加价
  addedValue = accountingTotalValue - metalValue
  baseCurAddedValue = baseCurAccountingTotalValue - baseCurMetalValue

  ▎ 逻辑：没有定价记录时，用 SCO 市场价格作为金属单价，乘以数量得到金属价值，再
  ▎ 用记账金额减去金属价值反推出附加价。注意这里和路径B1的推导方向相反：B1是先算
  ▎ 附加价再推金属价，B2是先算金属价再推附加价。

  第三层：CD Note 调整（1320-1338行）

  如果该入库明细有附加价类型的 CD Note 发票（CdValuationType = 
  ADDED_VALUE），会对金属价和附加价做再分配：

  cdAddedValue = CD Note发票的不含税金额

  addedValue = addedValue + cdAddedValue        // 附加价增加CD金额
  metalValue = metalValue - cdAddedValue        // 
  金属价减少CD金额（保持总额不变）

  // 本位币按比例调整
  baseCurAddedValue = (addedValue + cdAddedValue) / addedValue ×
  baseCurAddedValue
  baseCurMetalValue = (metalValue - cdAddedValue) / metalValue ×
  baseCurMetalValue

  ▎ 逻辑：CD Note 的附加价部分从金属价"转移"到附加价，记账金额（metalValue + 
  ▎ addedValue）总量不变。

  核心公式总结

  整个计算链条的核心恒等式是：

  accountingTotalValue = metalValue + addedValue

  但推导方向因场景不同而不同：

  ┌────────┬───────────────────────────┬───────────────────────────────────┐
  │  场景  │         推导方向          │               原因                │
  ├────────┼───────────────────────────┼───────────────────────────────────┤
  │ 原材料 │ metalValue = accountingTo │ 原材料无加工附加值                │
  │  Z001  │ talValue，addedValue = 0  │                                   │
  ├────────┼───────────────────────────┼───────────────────────────────────┤
  │ 非原材 │ 先算 addedValue → 反推    │ 有 MovementPrice 的               │
  │ 料 +   │ metalValue                │ additionalPrice                   │
  │ 已定价 │                           │ 字段可直接算附加价                │
  ├────────┼───────────────────────────┼───────────────────────────────────┤
  │ 非原材 │ 先算 metalValue（SCO价格× │ 没有定价记录，只能用市场参考价估  │
  │ 料 +   │ 数量）→ 反推 addedValue   │ 算金属部分                        │
  │ 未定价 │                           │                                   │
