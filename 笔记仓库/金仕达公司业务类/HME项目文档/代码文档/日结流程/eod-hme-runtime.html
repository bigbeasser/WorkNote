HME · EOD Runtime · Deep Dive

日结批处理如何一步步跑完

从页面接口 PUT /api/jobs/execByTaskName/EOD-hme 启动， 经 Quartz 与 Activiti 编排，每个 Delegate 只做自己的 process。 下文展开每步计算了什么、目的、写哪些表。

总览：触发到结束

形状表示类型：椭圆为起止，矩形为步骤，菱形为决策。焦点步骤用强调色标出。

单步模板：开始执行 / 执行失败从哪来

所有 HME*EODDelegate 共享 BaseActivityDelegate.execute。 子类只需实现 process；注解文案写入任务日志的「任务名」。

以 Brass Scorporo 为例：日志里的 START/END 是类内 StopWatch；「开始执行/执行结束」来自基类；「完成/失败」来自 EODServiceImp 业务日志。

ENTRY

怎么触发

  • PUT /api/jobs/execByTaskName/EOD-hme
  • 硬编码 JobId=16，流程 key=inside_1ilb
  • 价校验失败则整次不启动

PATTERN

每步只干一件事

  • Delegate 薄封装 → 调一个 Service 方法
  • 开关来自对接配置 EodControl
  • 上下文从 Redis EOD:* 灌入

LOOP

多机构如何串

  • Finish 后再次 execution 同一 Job
  • 从 EOD:LegalEntityIds pop 下一机构
  • 队列空 → Status=SUCCEED

逐步深入：计算 · 目的 · 落库

几乎每步都会写 curvedate_session_log。下列「写表」只列业务主表。 Brass 若干落库代码在 ForwardPriceServiceImpl 中已被注释——页面用「半落库」标签标出。 完整文字版见 eod_hme_runtime_guide.md §八。

12

Finish 收尾 / 多机构循环

HMEFinishEODDelegate
目的
标记本机构流程结束，再触发同一 Job 处理下一机构。
计算 / 动作
日志「日结操作已完成」→ Redis TEMP_COMPLETE + Finished 标记 → 删 LegalEntityId → quartzJobService.execution 再次弹出下一机构；队列空则 SUCCEED。
读表
sys_quartz_job
写表
curvedate_session_log（+ 调度日志）
