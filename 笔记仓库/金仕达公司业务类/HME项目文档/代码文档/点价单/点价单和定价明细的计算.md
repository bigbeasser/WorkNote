# 点价单创建与定价计算

> 从订单创建到点价单生成，再到价格计算的完整链路

相关文档：[[pricing-formula-developer-guide]] · [[cashflow-pricing-formula-trace]] · [[python-pricing-engine-trace]]

---

## 一、核心结论

**点价单以手动创建为主，自动创建为辅。**

| 创建方式 | 触发场景 | 占比 |
|---|---|---|
| **手动** | 用户在 UI 选择合同行 → 填写点价信息 → 保存 → 提交 | 主要 |
| **CRM 推送** | CRM 系统调用 `/api/docking/crm/receiveFixationOrder` | 辅助 |
| **公司间自动** | BTO/BTS 出库/入库登记时自动生成并提交 | 特定场景 |
| **批量导入** | 用户上传 Excel 导入 | 辅助 |

**没有定时任务自动创建点价单。** EOD 只更新已提交点价单的价格，不创建新单。

## 二、实体结构

### 2.1 Pricing（主表）

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | Long | 主键（雪花 ID） |
| `documentType` | String | `"1"` = 转计价单，`"2"` = 点价单 |
| `pricingNo` | String | 自动编号（序列 `price_order_number`） |
| `pricingDate` | LocalDate | 单据日期 |
| `physicalDealId` | Long | 关联合同 |
| `psFlag` | String | `P` = 采购，`S` = 销售 |

| `intercompany` | String | 公司间类型（BTO/BTS 触发自动下游单据） |
| `dataSource` | String | 来源（`CRM` / 空=手动） |

### 2.2 PriceTriggering（明细表）

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | Long | 主键 |
| `fixationId` | String | 唯一点价编号（如 `FX30230328_00023`） |
| `pricingId` | Long | FK → Pricing.id |

| `detailsType` | Integer | `1` = 点价记录，`2` = 点价变更 |

| `basePrice` | Double | 基价 |
| `spread` | Double | 升贴水 |
| `otherExpenses` | Double | 其他费用 |
| `price` | Double | **成交价格 = basePrice + spread + otherExpenses** |
| `metalPrice` | Double | 金属价（拆价） |
| `additionalPrice` | Double | 附加价 = price - metalPrice |
| `transferFee` | Double | 调期费 |
| `onSpotPrice` | Integer | `0`=未知 `1`=现货价 `2`=已知价 |
| `hasBasePrice` | Boolean | 基价是否已知 |
| `status` | Integer | `0`=初始 `1`=变更中 `2`=已提交 |
| `priceStatus` | Integer | `1`=未确认 `2`=已确认 |
| `triggerDate` | LocalDate | 点价时间 |
| `transactionDate` | LocalDate | 成交日期 |
| `session` | Integer | 交易场次（现货=99） |
| `forwardContractId` | Long | 远期合约月份 |
| `forwardCurveId` | Long | 远期曲线 |

### 2.3 关系

```
PhysicalDealLine (合同商品行)
  │
  ├── 1:N ── PriceTriggering (点价明细)
  │           一个商品行可以有多条点价记录
  │           通过 physicalDealLineId 关联
  │
  └── N:1 ── Pricing (点价主表)
              通过 physicalDealId 关联合同
```

│ 2. 预填表单                                                  │

                                │

### 3.2 关键校验

| 校验 | 方法 | 规则 |
|---|---|---|
| 时间窗口 | `checkAllowedPricing()` | 当前时间在 `AllowedPricingBeginTime` ~ `AllowedPricingEndTime` 之间 |
| 重复提交 | `checkUnsubmittedPricingOnOtherOrders()` | 同一合同行不能有其他未提交的点价单 |
| 量上限 | `checkData()` | 点价量 ≤ 合同行量 × (1 + 溢短率)，减少/取消类型跳过 |
| 日结冲突 | 检查 Redis `EOD:control` | 日结处理中时禁止操作 |

## 五、点价明细价格计算

### 5.1 calBasePrice() — 基价计算

**文件**: `PricingServiceImpl.java` L3374-3610

这是点价单中最核心的计算方法，从远期曲线数据计算基价。

```
输入: 合同行 + 点价日期 + 远期合约月份
  │
  ▼
┌─────────────────────────────────────────────────────────────┐
│ 1. 解析计价公式参数                                          │
│    pricingFormulaIdParameters JSON → abbreviation, curveId  │
└───────────────────────────────┬─────────────────────────────┘
                                │
                                ▼
┌─────────────────────────────────────────────────────────────┐
│ 2. 获取商品成分（规格）                                      │
│    specificationTypeMapper → 按 productId 查询               │
│    过滤 category = "Fixation" 的成分                         │
│    每个成分有: coefficient(系数), type(类型), marker(标记)    │
└───────────────────────────────┬─────────────────────────────┘
                                │
                                ▼
┌─────────────────────────────────────────────────────────────┐
│ 3. 查询远期价格                                              │
│    ForwardPrice 表:                                          │
│    WHERE forwardContractId = ? AND date = 点价日期           │
│    AND marketPriceType = ? AND session = ?                   │
└───────────────────────────────┬─────────────────────────────┘
                                │
                                ▼
┌─────────────────────────────────────────────────────────────┐
│ 4. 逐成分计算并累加                                          │
│    对每个成分:                                               │
│    │                                                         │
│    ├── 取 marketPriceValue (远期曲线市场价格)                 │
│    │                                                         │
│    ├── 币种转换:                                              │
│    │   exchangeRate = getExchangeRateByPub(                  │
│    │       曲线币种 → 合同结算币种, 日期, 外汇市场)           │
│    │   price *= exchangeRate                                 │
│    │                                                         │
│    ├── 单位转换:                                              │
│    │   unitConversion = getUnitConversion(                   │
│    │       曲线单位 → 合同量单位, productId)                  │
│    │   price /= unitConversion                               │
│    │                                                         │
│    ├── 规格系数:                                              │
│    │   if type == "content" (含量):                          │
│    │       price *= coefficient / 100                        │
│    │   if type == "proportion" (比例):                       │
│    │       price *= coefficient                              │
│    │                                                         │
│    └── 累加: basePrice += price                              │
│                                                             │
│    basePrice = Σ(成分价格 × 汇率 × 单位换算 × 系数)          │
└─────────────────────────────────────────────────────────────┘
```

### 5.2 spread — 升贴水计算

```
从 pricingFormulaIdParameters 中提取 level=2 的参数:

if BasicFixedPremium:
    spreadValue = formula_parameters.basicSpread.value

    if percentage == "y" (百分比模式):
        spread = spreadValue × basePrice
    else (固定值模式):
        spread = spreadValue
        → 币种转换 (spreadCurrency → settlementCurrency)
        → 单位转换 (spreadUnit → contractUnit)

if PercentPremium:
    percentSpreadValue = formula_parameters.basicSpread.value
    spread = percentSpreadValue × basePrice

最终: totalSpread = newSpread + oldSpread
      (PercentPremium 部分 + BasicFixedPremium 部分)
```

### 5.3 otherExpenses — 其他费用

```
从 level=3/4 的公式组件提取:
  ProcessingFee → 加工费
  AddedValue → 附加价值

与 spread 类似，做币种+单位转换后累加
```

### 5.4 最终价格公式

```
price = basePrice + spread + otherExpenses

metalPrice = 金属拆价（从 scorporo 价格表查询，或 = price）
additionalPrice = price - metalPrice
dealAmount = price × quantity
```

### 5.5 现货价 vs 远期价

| 类型 | onSpotPrice | 基价来源 | session |
|---|---|---|---|
| **现货价** | `1` | 用户手动输入或 CRM 传入 | `99` |
| **已知远期价** | `2` | `calBasePrice()` 从远期曲线计算 | 最新场次 |
| **未知价** | `0` | 待日结确定 | 最新场次 |

### 6.1 调用链

### 6.2 generateByPricing() — 新建 MovementPrice

```
MovementPrice 字段映射:
  physicalDealLineId = PriceTriggering.physicalDealLineId
  quantity = -PriceTriggering.quantity (采购取负)
  priceDate = PriceTriggering.triggerDate
  dailySettlementDate = 曲线日期
  refDocumentType = 4 (点价记录)
  refContractNumber = PriceTriggering.fixationId

  if priceDate <= dailySettlementDate:
      priced = 1, movementActionType = FID (价格已确定)
  else:
      priced = 0, movementActionType = FIX (待日结激活)

  valid = 1
```

**文件**: `MovementPriceServiceImpl.java` L2974-3069

## 十、常见问题

### Q1: 一个合同行可以有多少条点价记录？
没有上限。每次点价创建一条 `PriceTriggering`，累计点价量不能超过合同行量 × (1 + 溢短率)。系统通过 `quantityCanBePriced = 未定价量 + 溢短量` 控制。

### Q2: 点价单保存后价格可以改吗？
可以。保存后 `status=0`（初始），可以随意修改。提交后 `status=2`，需要通过"变更"流程（创建 `detailsType=2` 的变更记录）。

### Q3: `onSpotPrice` 三种值有什么区别？
- `0`（未知）：基价尚未确定，需要等日结 EOD 从远期曲线取价
- `1`（现货价）：用户手动输入基价，`session=99`，提交即确定
- `2`（已知价）：系统从远期曲线计算的基价，提交即确定

### Q4: 提交后 MovementPrice 的 quantity 为什么是负数？
采购方向（`ps_flag='P'`）的 MP 记录 quantity 为负。这是系统的符号约定，表示"买入"方向。`PriceTriggering.quantity` 始终为正。

### Q5: 公司间（BTO/BTS）为什么是全自动的？
公司间贸易的出库和入库是配对操作。出库时自动生成销售侧点价单并提交，入库时复制销售侧的价格生成采购侧点价单并提交。全程无需人工干预，确保两侧价格一致。

### Q6: 点价和现金流的关系？
点价单保存时，如果 `hasBasePrice=true`，会立即触发 `generateCashFlowModel()` 更新现金流。提交时通过 `updateByPricingCommit()` 生成 MovementPrice，MovementPrice 是库存定价报表的核心数据源。
