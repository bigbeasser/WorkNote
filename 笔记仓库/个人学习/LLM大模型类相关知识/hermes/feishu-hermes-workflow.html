飞书 × Hermes Agent 工作流程

消息从飞书发出 → 经 Gateway 转发 → Agent 处理 → 回复飞书

场景一：查询服务器状态

  • • 用户在飞书发: "查一下生产服务器 CPU 使用率"
  • • Gateway 接收 → Agent 解析意图
  • • Agent 调用 terminal 工具: ssh + top/htop
  • • LLM 整理输出，格式化为易读报告
  • • 回复发回飞书，用户直接看到结果

场景二：操作飞书文档

  • • 用户在飞书发: "把本周会议纪要写入文档"
  • • Agent 调用 feishu_doc 工具创建文档
  • • 调用 terminal 搜索本周相关聊天记录
  • • LLM 汇总整理成结构化纪要
  • • feishu_doc 写入内容，返回文档链接

场景三：代码审查与部署

  • • 用户在飞书发: "review 一下 main 分支最新 PR"
  • • Agent 调用 terminal 执行 git/gh 命令
  • • 读取 diff，LLM 逐文件审查代码质量
  • • 调用 web 工具搜索最佳实践参考
  • • 返回审查意见 + 是否可合并的建议

场景四：定时巡检推送

  • • 配置 Cron: 每天早上 9 点执行巡检
  • • Agent 自动检查数据库、API、磁盘空间
  • • 汇总异常项，生成巡检报告
  • • 通过 Gateway 主动推送到飞书群
  • • 无需人工触发，全自动运行

场景五：数据分析与可视化

  • • 用户在飞书发: "分析上月销售数据画个趋势图"
  • • Agent 调用 terminal 读取 CSV/数据库
  • • 用 Python 做数据清洗和统计分析
  • • 生成 matplotlib 图表保存为图片
  • • 图片 + 文字分析一起发回飞书

关键配置要点

  • • hermes gateway setup → 配置飞书 App ID/Secret
  • • 飞书开放平台开启事件订阅 (im.message.receive_v1)
  • • 配置 Request URL 指向 Hermes Gateway 地址
  • • hermes gateway install → 安装为后台服务
  • • 支持私聊和群聊 @机器人 两种触发方式
